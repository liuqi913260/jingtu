# 竞途（JingTu）产品需求文档

> 版本：V1.0 MVP
>
> 状态：第一版开发依据
>
> 更新日期：2026-10-27

## 0. 文档说明

竞途是面向大学生的竞赛信息总览与组队协作平台。第一版先做成可在浏览器运行的网页 App，重点验证三个问题：

1. 学生能否快速发现适合自己的比赛。
2. 学生能否发布、查找并联系竞赛队友。
3. 学生能否通过结构化知识内容完成基础备赛。

第一版允许使用浏览器本地数据完成完整演示，不依赖真实后端服务。数据模型和页面结构需要为后续接入服务端数据库、真实鉴权和即时通信保留扩展空间。

## 1. 产品目标和使用场景

### 1.1 产品目标

- 汇总大学生常见竞赛信息，降低“想参赛但不知道有哪些比赛”的信息获取成本。
- 用统一字段展示比赛学校/主办方、比赛名称、比赛内容、类别、状态和截止时间。
- 帮助没有固定队伍的学生寻找技能互补的伙伴，解决“想参加比赛但找不见队友”的问题。
- 收集数学建模、创新创业、学术科技、设计创意、答辩路演等备赛知识，提供从入门到进阶的内容入口。
- 让学生可以发布比赛和组队招募，形成由用户共同补充的竞赛信息和协作网络。

### 1.2 主要用户

- **参赛学生**：浏览比赛、筛选方向、查看截止时间、收藏或进一步了解比赛。
- **组队发起人**：发布比赛项目或招募需求，说明项目情况和需要的角色。
- **备赛学习者**：按竞赛方向查找经验、方法论和基础知识。
- **信息贡献者**：补充自己学校或社群中了解到的比赛信息。

### 1.3 核心使用场景

1. 新生或第一次参赛的学生进入首页，查看热门赛事、近期截止和推荐知识，快速找到感兴趣的方向。
2. 学生在赛事广场按类别筛选比赛，查看比赛内容、主办方和截止日期。
3. 学生想参加数学建模但缺少队友，进入“找队友”，按角色和方向查看招募，联系队长或发布自己的招募。
4. 学生知道一个平台尚未收录的比赛，登录后填写学校/主办方、比赛名字、比赛内容、类别、截止日期和状态，发布到赛事广场。
5. 学生进入知识库学习比赛准备方法，再回到赛事广场或找队友完成行动。
6. 用户在本地浏览器中导出数据作为备份，换设备或清空浏览器后通过导入文件恢复。

## 2. 整体页面框架和导航结构

### 2.1 页面框架

采用桌面端优先、移动端自适应的后台工作台式布局：

```text
应用外壳
├── 左侧导航栏
│   ├── 品牌：竞途
│   ├── 工作台
│   │   ├── 首页总览
│   │   ├── 赛事广场
│   │   ├── 找队友
│   │   └── 知识库
│   ├── 我的
│   │   ├── 我的发布
│   │   └── 个人资料
│   └── 当前用户与登录入口
├── 顶部栏
│   ├── 面包屑 / 当前页面名称
│   ├── 全局搜索
│   ├── 通知入口（第一版可为占位）
│   └── 发布比赛
└── 主内容区
    └── 当前模块页面
```

### 2.2 导航规则

- 默认进入“首页总览”。
- 左侧导航始终可见；移动端收缩为图标导航。
- 当前页面导航项必须有明显选中状态。
- 顶部“发布比赛”在任意页面可用；未登录时先进入登录/注册流程。
- 全局搜索至少覆盖比赛名称、比赛内容、学校/主办方和找队友招募标题。
- 未登录用户可以浏览公开内容；发布、联系队长、查看“我的发布”等需要登录。
- 所有页面需要提供空状态、加载状态和操作成功/失败提示。

## 3. 首页的内容结构

首页是用户登录后或游客进入 App 的第一屏，目标是让用户在一次浏览内知道“有什么比赛、哪些快截止、哪里能学、哪里能找队友”。

### 3.1 顶部欢迎区

- 个性化问候；游客显示“今天，也为热爱出发”。
- 一句产品价值说明：发现值得参加的比赛，遇见一起并肩作战的伙伴。
- 两个主要操作：**浏览赛事**、**发布比赛**。

### 3.2 数据概览卡片

第一版显示四项汇总：

- 平台赛事：当前可见比赛总数。
- 正在招募的队伍：当前公开招募总数。
- 知识内容：知识库条目数量。
- 我的收藏：当前用户收藏数量；未登录显示登录提示或 0。

统计数字必须由实际数据计算，不能只写死在页面中。

### 3.3 热门赛事

- 展示 3–4 条热门或推荐比赛。
- 每条显示比赛名称、学校/主办方、类别、报名状态、截止日期。
- 提供“查看全部”入口进入赛事广场。

### 3.4 近期截止

- 展示近期需要关注的比赛截止节点。
- 每项显示日期、月份、比赛名称、节点类型和剩余天数。
- 点击后进入对应比赛详情或赛事广场。

### 3.5 找队友入口

- 展示 1–2 条最新组队招募。
- 显示招募标题、队伍人数/现状、发布时间。
- 提供“去找队友”入口。

### 3.6 备赛知识入口

- 展示 3 个知识方向卡片。
- 第一版方向至少包括：数学建模入门、互联网+备赛指南、高效组队方法。
- 提供“进入知识库”入口。

## 4. 每个模块的用途

| 模块 | 用途 | 主要结果 |
| --- | --- | --- |
| 首页总览 | 汇总全站重要信息，帮助用户快速决定下一步 | 进入赛事、学习知识或找队友 |
| 赛事广场 | 浏览、搜索、筛选和查看比赛信息 | 找到合适的比赛并记住截止节点 |
| 找队友 | 发布和浏览竞赛组队招募 | 建立队伍、联系潜在队友 |
| 知识库 | 按方向沉淀竞赛知识和经验 | 完成基础备赛学习 |
| 我的发布 | 管理自己发布的比赛和招募内容 | 查看、复盘自己的贡献 |
| 个人资料 | 保存学校、昵称和竞赛偏好 | 让队友了解自己，改善推荐 |
| 登录/注册 | 建立本地用户身份 | 解锁发布、联系和个人数据 |
| 全局搜索 | 跨模块快速寻找关键词 | 减少逐页查找成本 |

## 5. 每个模块第一版最必要的数据和操作

### 5.1 登录/注册

**必要数据**：

- 用户 ID（本地生成）。
- 邮箱或手机号（第一版作为登录账号）。
- 密码（第一版只用于本地原型流程；不得宣称为真实安全鉴权）。
- 昵称。
- 学校。
- 创建时间、最近登录时间。

**必要操作**：

- 登录。
- 注册。
- 退出登录。
- 登录状态在刷新后保持。
- 未登录发布或联系队友时跳转登录。

### 5.2 首页总览

**必要数据**：由赛事、招募、知识、收藏数据实时汇总。

**必要操作**：

- 点击热门赛事进入赛事广场或详情。
- 点击截止节点进入相关比赛。
- 点击找队友/知识卡片进入对应模块。
- 点击发布比赛打开发布表单。

### 5.3 赛事广场

**比赛数据**：

- 比赛 ID。
- 学校/主办方。
- 比赛名字。
- 比赛内容。
- 比赛类别：创新创业、学术科技、数学建模、设计创意等。
- 报名截止日期或作品提交日期。
- 状态：报名中、即将开始、已结束。
- 热度/推荐标记。
- 发布者用户 ID、创建时间、更新时间。

**必要操作**：

- 浏览赛事卡片或列表。
- 按类别筛选。
- 按地区/范围筛选（第一版可先保留控件和基础选项）。
- 按截止日期或热度排序。
- 关键词搜索。
- 查看比赛详情。
- 登录后发布比赛。
- 登录后收藏/取消收藏（若第一版实现收藏，必须持久化）。

### 5.4 找队友

**招募数据**：

- 招募 ID。
- 发布者用户 ID、昵称、学校。
- 招募标题。
- 关联比赛名称或比赛 ID。
- 项目/队伍说明。
- 需要的角色列表。
- 当前队伍人数或招募状态。
- 发布时间、更新时间。

**必要操作**：

- 浏览招募卡片。
- 按方向或角色筛选。
- 查看招募说明。
- 登录后发布招募。
- 登录后点击“联系队长”，第一版可以先用成功提示模拟联系。
- 查看自己发布的招募。

### 5.5 知识库

**知识数据**：

- 内容 ID。
- 标题。
- 摘要。
- 所属方向/标签。
- 正文或内容地址。
- 阅读时间。
- 创建时间、更新时间。

**第一版内容方向**：数学建模入门、互联网+备赛指南、高效组队方法、学术论文写作、设计创意表达、答辩与路演。

**必要操作**：

- 浏览分类卡片。
- 查看精选内容摘要。
- 打开知识内容详情。
- 按方向筛选。

### 5.6 我的发布

**必要数据**：当前用户发布的比赛和招募，关联原始记录 ID。

**必要操作**：

- 查看自己的发布列表。
- 查看详情。
- 第一版至少支持删除自己的记录；编辑可以作为后续小版本。
- 未登录显示登录引导和空状态。

### 5.7 个人资料

**必要数据**：昵称、学校、专业（可选）、竞赛方向偏好、头像首字母。

**必要操作**：

- 查看个人资料。
- 编辑昵称、学校和竞赛方向。
- 查看我的发布数量、参与赛事数量、收藏数量。

### 5.8 本地数据和备份恢复

**必要数据集合**：`users`、`currentUser`、`competitions`、`recruitments`、`knowledge`、`favorites`、`settings`。

**必要操作**：

- 导出全部本地数据为一个 JSON 文件。
- 从合法 JSON 文件导入数据。
- 导入前校验版本、字段和数据类型。
- 导入前提示将覆盖或合并现有数据。
- 导入失败时保留原数据并给出错误原因。
- 提供“恢复默认示例数据”操作。

## 6. 首页、今日计划和各个模块之间的关系

### 6.1 “今日计划”的定位

“今日计划”是首页中的行动聚合区，用来把分散在赛事、知识库和找队友中的下一步行动集中展示。它不是一个独立的内容生产模块，第一版可以先以首页区块或轻量任务列表实现。

### 6.2 今日计划的第一版数据

- 计划 ID。
- 当前用户 ID；游客可以使用临时本地计划。
- 来源类型：比赛、知识内容、组队招募。
- 来源记录 ID。
- 计划标题。
- 计划日期，默认今天。
- 完成状态。
- 创建时间、完成时间。

### 6.3 今日计划的必要操作

- 从比赛详情添加“今天关注/报名准备”计划。
- 从知识内容添加“今天学习”计划。
- 从找队友添加“今天联系/完善招募”计划。
- 在首页查看今天的计划数量和列表。
- 勾选完成或取消完成。
- 计划来源点击后回到对应模块。

### 6.4 模块关系

```text
首页总览
├── 汇总赛事广场的数据 ──→ 热门赛事 / 近期截止
├── 汇总找队友的数据 ───→ 最新招募
├── 汇总知识库的数据 ───→ 推荐知识
└── 汇总今日计划 ───────→ 用户今天的行动

赛事广场 ──添加计划──→ 今日计划 ──点击来源──→ 比赛详情
知识库   ──添加计划──→ 今日计划 ──点击来源──→ 知识详情
找队友   ──添加计划──→ 今日计划 ──点击来源──→ 招募详情
```

首页负责“发现和分发行动”，各个模块负责提供可执行内容，今日计划负责将内容转成当天要做的事情。第一版如果开发资源有限，今日计划可以先实现“首页展示 + 手动勾选完成”，不做提醒推送和复杂日历。

## 7. 本地数据文件、备份和恢复要求

### 7.1 存储策略

- 浏览器运行版使用 `localStorage` 保存轻量数据；如数据量增大，存储层应可替换为 IndexedDB。
- 页面刷新后数据不能丢失。
- 数据层与 UI 解耦，不能把业务数据只写在页面模板或硬编码数组中。
- 所有写入统一经过版本化的存储函数，避免不同页面使用不同 key 造成数据不一致。

### 7.2 建议本地数据文件格式

导出文件建议命名为 `jingtu-backup-YYYYMMDD-HHmm.json`，结构如下：

```json
{
  "app": "jingtu",
  "schemaVersion": 1,
  "exportedAt": "2026-10-27T00:00:00.000Z",
  "data": {
    "users": [],
    "currentUser": null,
    "competitions": [],
    "recruitments": [],
    "knowledge": [],
    "favorites": [],
    "todayPlans": [],
    "settings": {}
  }
}
```

### 7.3 备份要求

- 用户点击“导出备份”后下载 JSON 文件。
- 导出内容应包含用户自己创建的数据、收藏、今日计划和必要设置。
- 导出前不应把密码以明文写入备份文件；第一版如果无法安全处理，应排除密码字段并在界面说明。
- 导出成功显示文件名和记录数量。

### 7.4 恢复要求

- 支持选择本地 JSON 文件导入。
- 必须校验 `app` 和 `schemaVersion`。
- 缺少必需字段、字段类型错误或 JSON 损坏时拒绝导入。
- 导入前弹窗说明：覆盖现有数据或合并数据。第一版至少实现覆盖恢复。
- 恢复成功后刷新统计数字、列表、个人页和首页。
- 恢复失败不得清空现有数据。
- 未来 schema 升级需要提供迁移函数，例如 `v1 -> v2`。

## 9. 第一版暂时不做的功能

以下功能保留产品方向，但不作为 V1.0 的上线门槛：

- 真实服务器账号体系、短信验证码、邮箱验证、OAuth/微信登录。
- 密码找回、二次验证、角色权限和管理员后台。
- 真实私信、群聊、语音/视频和实时在线状态。
- 站内报名、报名材料上传、支付和赛事成绩回传。
- 自动从教育部、赛事官网或第三方平台抓取并同步比赛。
- 复杂推荐算法、基于履历的智能匹配和 AI 自动组队。
- 公开评论、点赞、关注、举报和完整社区审核机制。
- 多端云同步、跨设备同步和服务端备份。
- 推送通知、短信提醒、邮件提醒和系统日历双向同步。
- 富文本编辑器、视频课程、直播、附件和大文件上传。
- 地图、定位、学校认证和校园组织认证。
- 完整的多语言国际化。
- 复杂的日历视图、重复任务、优先级、依赖关系和统计报表。

## 10. 可以实际检查的验收标准

### 10.1 页面和导航

- 打开 `index.html` 后默认显示首页总览，不出现空白页、未捕获异常或破损布局。
- 点击左侧“赛事广场、找队友、知识库、我的发布、个人资料”，每次只显示对应页面，导航项选中状态同步更新。
- 在宽屏和手机宽度下，内容不出现横向溢出；主要按钮可点击。

### 10.2 登录和用户状态

- 未登录点击“发布比赛”或“发布招募”时，能看到登录/注册窗口。
- 注册后显示用户昵称和学校；刷新页面后仍为登录状态。
- 退出登录后恢复游客状态；受保护操作再次要求登录。
- 必填字段为空时，表单不能提交，并显示浏览器或产品级校验提示。

### 10.3 赛事功能

- 新建比赛后，比赛立即出现在赛事广场顶部或列表中。
- 比赛至少显示学校/主办方、比赛名字、比赛内容、类别、状态和截止日期。
- 选择类别筛选后，只显示对应类别比赛；恢复“全部类别”后列表恢复。
- 在搜索框输入已知比赛名称并回车，能看到匹配结果；无匹配时显示空状态。
- 刷新页面后，新建比赛仍存在，首页统计数字同步变化。

### 10.4 找队友功能

- 新建招募后，招募立即出现在找队友列表。
- 招募卡片至少显示发布者、学校、标题、说明、角色标签和当前人数/状态。
- 未登录联系队长时进入登录流程；已登录联系队长时显示明确的成功反馈。
- 刷新页面后，新建招募仍存在。

### 10.5 知识库和今日计划

- 知识库至少能看到六个约定方向中的内容卡片。
- 点击知识卡片后能进入内容或看到完整内容摘要，不出现无响应按钮。
- 比赛、知识内容或招募至少有一个入口可以添加到今日计划。
- 首页能看到今日计划条目，勾选后状态变为已完成，刷新后状态保持。

### 10.6 本地备份与恢复

- 点击导出后下载合法 JSON 文件，文件包含 `app`、`schemaVersion`、`exportedAt` 和 `data`。
- 导出的备份不包含明文密码。
- 导入刚导出的文件后，用户、比赛、招募、收藏和今日计划可以恢复。
- 导入损坏 JSON 或错误版本文件时，页面给出错误提示，原数据仍然存在。
- 执行“恢复默认示例数据”前有确认提示，确认后首页和列表恢复到默认数据。

### 10.7 质量要求

- JavaScript 无语法错误，浏览器控制台无阻断首屏渲染的错误。
- 页面主要数据来源于统一状态/存储层，不能只修改页面文本而不修改数据。
- 所有 P0 功能可以在无网络环境下完成基本演示。
- 页面文本、按钮和错误提示使用中文，字段含义与本 PRD 一致。

## 附录：建议开发顺序

1. 建立数据模型、版本化本地存储和默认示例数据。
2. 完成应用外壳、导航和首页总览。
3. 完成登录/注册和当前用户状态。
4. 完成赛事广场、比赛详情和发布比赛。
5. 完成找队友和发布招募。
6. 完成知识库和精选内容。
7. 完成今日计划、收藏和我的发布/个人资料。
8. 完成本地导出、导入、校验和恢复。
9. 按第 10 节逐条验收，并在桌面端和手机宽度回归检查。
